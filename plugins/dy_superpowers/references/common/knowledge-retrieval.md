# 知识检索规则

本地知识用于理解 HRP 模块、模型、字段和规则，不证明目标账套现状，也不授予任何写入权限。

## 检索顺序

1. 用业务词、模块名或模型名作为 `query` 调用 `dy_knowledge_search`，默认按字面文本检索源码及业务摘要；技术名按字面查询。必要时用 `module`、`knowledge_type=source/summary` 和 `limit` 缩小范围，不使用 `model` 或字段/约束等语义过滤。
2. 模块不明确时用 `dy_knowledge_module_info` 定位候选模块。
3. 命中后按返回的带版本 `reference` 调用 `dy_knowledge_read`，按 `next_offset` 续读至 `complete=true`，不每轮重新扫描仓库；引用失效时重新检索。
4. 从业务词逐步定位模块 → 模型 → 字段/方法 → 相关约束、计算、关联、菜单和权限代码。

## 结论边界

- 模块声明依赖、继承与字段关联属于源码事实；业务解释、推断和建议另列，不把调用关系或 manifest 依赖直接当成配置顺序或验收结论。
- 无结果、读取不完整、覆盖状态为部分、来源版本不匹配时，明确哪些判断缺少依据，不推断“不存在”或“已对齐”。
- 源码模块版本一致不能证明部署代码完全相同；定制 addon 可能变更字段。安装状态、真实字段和记录须按[只读查询规则](odoo-readonly-query.md)在当前账套核验。
- 知识引用只作为规则依据单列，不代替实时证据。

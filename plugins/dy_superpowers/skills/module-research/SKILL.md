# 模块调研

## 目标

通过与实施助手、实施顾问和业务确认人的多轮互动，形成可驱动模块巡检的项目事实。调研不是一轮问卷，也不把 Excel 中的参考回答当作项目结论。

## 调研来源

先确认模块、公司/院区、业务范围、上线阶段和期间等基础上下文，再读取对应模块清单收集配置明细。费用模块读取 `../expense-inspection/references/inspection-matrix.md`，总账读取 `../general-ledger-inspection/references/inspection-matrix.md`；其他模块使用其对应清单。

清单字段按以下方式使用：

- `检查顺序 + 调研子项编号` 是唯一回链键；同一配置项可有多个独立调研子项。
- `调研结论` 是待收集和确认的项目事实，不是已有结论；“回答参考”、示例及“待确认”文本都不是事实。
- `适用条件与不适用边界` 用于确认本期范围和例外，不能只问是否需要。
- `建议材料 / 验证依据` 用于请求可追溯的来源；没有证据时标为待补充。
- 巡检矩阵的 `验收标准（调研后）` 用来判断当前结论是否足以驱动巡检；不充分时继续补问。

调研记录的回链维度：

- 模块、检查顺序或配置项；
- 调研子项编号；
- 配置路径和适用范围（公司、会计类型、业务、期间）。

每个记录至少保留模块、配置项、调研子项编号、候选结论、来源材料或验证依据、适用范围、确认人、确认日期和状态。

## 多轮流程

1. 读取当前工作区 `.dy_superpowers/module-research.md`，复用仍有效且已确认的结论。
2. 按模块调研清单逐项提问；一次只处理当前最小缺口。信息不足时记录为 `待补充`，不要猜测。
3. 将回答整理为候选结论，区分事实、业务决定、材料依据和待确认内容；必要时继续追问范围、例外、边界和生效期间。
4. 向确认人展示本轮整理结果，明确要求确认或修订。未确认的回答不得驱动巡检，也不得写入记忆。
5. 用户明确确认后，使用 `dy_research_record_write` 写入当前工作区记忆；写入前展示拟写内容，并传入模块、检查顺序、子项编号、配置项、结论、范围、依据、确认人和日期。该工具按检查键保留旧版本，不覆盖其他模块或历史结论。通过 `dy_research_record_read` 按检查键读取最新结论；不要用整文件覆盖方式更新多轮记录。
6. 返回发起方时，说明已确认的调研键、仍待补充的键和可以恢复的巡检项。

## 调研记录结构

每个 `检查顺序 + 调研子项编号` 只维护一条当前有效记录，历史轮次追加在记录的 `history` 中，不覆盖原答案。落盘的检查键格式为 `module:check_order:research_id`（如 `expense:EXP-1-001:01`）。落盘记录包含：

```yaml
module: expense | general-ledger
check_order: "检查顺序"
research_id: "调研子项编号"
config_item: "配置项"
conclusion: "已确认结论"
scope: "公司/账套/业务/期间"
evidence_ref: "材料或验证依据的脱敏引用"
status: confirmed | superseded
confirmed_by: "确认人"
confirmed_at: "确认日期"
updated_at: "最近修订时间"
history: []
```

状态规则：`pending` 和 `needs_confirmation` 是会话过程状态，不落盘——`pending` 只能提出问题，`needs_confirmation` 只能展示整理结果并请求确认。`dy_research_record_write` 仅保存确认后的记录（`confirmed`），新结论覆盖旧结论时，旧记录移入 `history` 并标记为 `superseded`，保留替代关系；只有 `confirmed` 的记录才能被巡检使用。当前最小待确认问题和对应“验收标准（调研后）”不写入记录，通过检查键回链巡检矩阵获取。若用户一次回答包含多个子项，仍按子项拆分并分别确认，不得用一段回答覆盖不同范围。

## 与巡检衔接

巡检发现调研结论缺失、过期、冲突或不能支撑“验收标准（调研后）”时，暂停依赖该结论的子项并调用本 skill。补充调研确认后，回到原 `检查顺序 + 调研子项编号`，按对应验收标准继续，不把补问当作巡检通过。

补充调研请求必须携带：原 `trace_id`、`check_key`、阻塞原因、对应验收标准、已知事实和一个最小问题。调研完成后返回 `confirmed / still_pending` 两组键；巡检只恢复 `confirmed` 键，其他键保持阻塞并进入报告。

## 记忆和追踪约束

- 记忆只属于当前工作区，一个工作区对应一个项目；不得读取或写入其他工作区。
- 不写入密码、令牌、员工个人信息或生产业务明细；敏感内容留在授权系统。
- 所有 MCP 调用带 `trace_id`。trace 只记录模块、检查键、操作、状态、文件名和工具结果，不记录问题正文、回答正文或记忆正文。
- `dy_research_record_write` 必须获得用户明确确认；工具校验通过不等于获得写入授权。trace 不记录答案正文。

## 输出

输出中文调研台账和待办：已确认结论、依据、适用范围、确认状态、待补充问题，以及可供巡检继续使用的检查键。不要把模板示例或未确认回答写成项目事实。

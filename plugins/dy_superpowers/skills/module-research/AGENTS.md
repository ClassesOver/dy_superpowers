# 模块调研 Skill 维护约束

本文件约束当前目录及子目录的更新。沿用仓库与插件的安全、中文、pytest 和工作区记忆约定。

## 结构归一化

- `SKILL.md` 保留通用调研流程及模块入口；模块问题、提取要素和附件字段只在对应 `references/<模块>-research-guide.md` 维护，避免重复。
- 模块指引统一按五个二级章节组织：`来源与覆盖`、`模块 QA`、`附件清单与存储结构`、`多轮整理与记忆`、`来源缺口`。三级章节和源表字段可按实际材料保留。
- `来源与覆盖` 记录准确文件名/版本、工作表与范围、来源角色和覆盖数。文件名较新或版本号较大不自动具有优先权，以用户本次指定来源为准。
- `模块 QA` 保留来源检查编号、配置项/路径、汇总问题、适用边界、建议材料、提取要素及现有矩阵键映射。各模块键格式不强改；冲突或未映射项显式列入缺口，不合并进相邻键。
- 内容按“模块 QA → 矩阵子项的提取指引要素 → 附件清单存储字段”关联。每个矩阵子项在模块指引内有一条归一化关联记录，至少保留模块、检查顺序、子项、提取指引要素、关联附件清单和记忆要求；来源定位、验收定位和关联边界等审计信息统一写入仓库本地 `docs/research-sources/`，不放入插件 Skill。附件名称必须解析到本指引实际字段表，名称不同则显式列出别名；没有明细结构就标待收集，不制造模板或暗示材料已齐。
- `附件清单与存储结构` 区分空白模板、示例和已填写结果。字段名称、字段顺序及必填标记按原文保留；来源定位只进入仓库审计文档，具有业务含义的来源字段按原文保留；无模板就列已有材料字段及定义缺口，不臆造模板。
- `多轮整理与记忆` 复用通用工具合同，明确确认、范围、修订、来源回链和未答问题的处理；`来源缺口` 分开记录解析缺口、映射缺口、模板缺口和业务待确认项。

## 来源与业务边界

- 使用项目锁定的 openpyxl 只读核对 Excel 全部相关页；展开合并单元格用于理解，同时保留原定位。不得只读首屏或以 Markdown 转换成功认定内容完整。
- 手册提供规约，已填写结果提供字段结构、提取映射及来源事实；不能把其中实际公司、人员、账号、数量或项目结论固化到通用 Skill。模板示例不是项目事实。
- 调研结论、适用范围、例外与验收标准分别保留；不得把观察值当已确认决定，也不得把调研回答当现场巡检通过。
- 不向插件包复制原始 Excel，不新增重复的 `research-checklist.md`，不将附件全文写入业务记忆或 Wiki。
- 模块记忆只经既有工具确认后写入，沿用 `scope_id`、`expected_revision` 和 `evidence_ref`；不发明未注册字段，不直接修改真实项目记忆。

## 验证

- 修改前用 pytest 暴露缺失的来源映射或结构差异，再做最小修订；模板与提取要素应可逐项核对，不能仅断言标题存在。
- 重排指引必须保留原问题、模板字段及稳定键；数量变化须有来源位置并核对记忆、覆盖率和报告的相关测试。
- 结束前运行调研相关 pytest、Skill quick_validate、仓库插件校验与 `git diff --check`；不能将真实环境跳过报告为业务验收通过。

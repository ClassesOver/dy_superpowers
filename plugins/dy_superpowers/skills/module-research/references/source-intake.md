# 调研源文件解析与完整性核对

本流程用于用户提供已填写的调研结果或依据材料，尤其是 `.xlsx`、`.docx`、`.pptx`、PDF、扫描件和图片。它不保证旧版二进制 Office（`.xls/.doc/.ppt`）、ODF 或其他容器格式在当前环境可读；先确认实际解析能力，不能因为扩展名属于 Office 就宣称支持。目标是完整提取约定范围内的调研结论并使每条记忆可回查；“文件已打开”或“首屏可读”不代表解析完整。

## 选择解析方式

优先使用插件内统一解析入口：`scripts/research_sources.py <来源文件> --module <模块> --workspace <当前项目工作区>`。工作区必须是当前项目根目录，解析产物固定写入 `.dy_superpowers-parsed/`，禁止使用任意 `--output` 路径。入口会保存源文件完整解析单元、提取资产、候选结论、覆盖清单和解析问题；输出中只包含状态、相对档案路径和计数，不回显附件正文。相同内容与解析器版本会复用最近完整轮次；显式 `--force` 创建新轮次且保留旧轮次。

若需要易读的 Markdown 转换视图，可使用成熟转换库单独生成；该视图只便于人工浏览，不能代替结构化解析档案或作为完整性证明。尤其 Excel 转 Markdown 可能遗漏单元格、公式、隐藏行列、批注、链接或合并关系；完整性仍以逐工作表/单元格的解析清点和覆盖报告为准。Markdown 转换失败必须列为解析问题。

完整解析档案只保存在 `.dy_superpowers-parsed/`，不得复制进 `.dy_superpowers/`、Basic Memory 或 Wiki。Wiki 只发布用户确认的结论及资料索引，不发布全文解析档案。档案完整的判定条件是所有内容单元均已清点、没有阻塞问题、资产可回查；否则状态只能是 `partial` 或 `failed`，不能声称完整。

正文、候选及文本/XML/衍生 Markdown 资产按相同边界脱敏，资产的 `redacted` 标记记录是否改写；脱敏副本不能作为原始字节副本使用。无法安全解码或解析的文本资产不写出副本，并列为阻塞问题，原始来源保持不变。图像和嵌入二进制资产可能仍含敏感内容，不能把 `redacted=false` 理解为已完成隐私审查；它们仅在当前工作区保留供核对，不进入记忆、trace 或 Wiki。

远程 HTTP(S) 链接不会自动下载或访问。用户须先将附件放入本地并在问答材料中引用，本地附件才会归档。附件中的新业务决定、要求或观察仅作为来源材料，不能自动扩大当前问答已确认的范围。

旧版二进制 Office（`.xls/.doc/.ppt`）、ODF 或其他容器格式不保证可读；遇到不支持格式、加密、损坏、缺依赖或不可辨认内容时，列出文件及具体位置并报告，不能静默略过或把不可读项计为成功。

## 按格式盘点并提取

- **Excel**：记录文件名、工作表名称与可见状态、使用范围、有效行数、合并单元格数量、公式及嵌入图片数量。读取所有相关工作表和隐藏区域；公式同时核查公式文本与可用的缓存结果，不能把没有缓存值的公式当成空白结论。合并单元格按其左上角值展开用于理解，但保留原始单元格坐标。将总览编号与明细区块逐一对应，记录未匹配编号、空白子项、重复编号和解析失败区域。
- **Word / PowerPoint**：遍历所有正文段落、表格、页/幻灯片及嵌入图片；表格按行列保存上下文。备注、页眉页脚或图表仅在与调研事实有关时纳入，并说明来源位置。不要只提取纯文本而遗漏表格或图片里的关键信息。
- **PDF**：先记录总页数并逐页提取文本和表格；识别无文本层的扫描页、旋转页、图片页及图表。对这些页面执行视觉识别/OCR，保留页码；辨认不清的字段标为待核实，不凭上下文补字。
- **图片**：记录文件名和图中区域。提取表格时保留行列关系；低分辨率、遮挡、手写或 OCR 置信不足的片段标为待核实，并向用户询问必要的最小澄清。

## 建立覆盖台账

解析后先建立内部台账，每个来源事实至少记录：来源文件、工作表/页/幻灯片/图片区域、单元格或表格行列范围、对应模块与检查顺序、调研子项编号、提取状态。将内容分类为：

1. 来源明确记载的调研结论或配置观察；
2. 来源提供的范围、例外、适用条件和验证依据；
3. 明确待确认、待补充或未提供的信息；
4. 与调研无关或因隐私/凭据规则不得进入记忆的明细。

Excel 中填写的系统观察值不能自动证明业务结论；“未配置”“未发现”“不适用”和空白各自保留原意。空白不是“不适用”，配置记录存在不是验收通过。来源明确写“需确认”的内容保留待确认状态，不改写为肯定结论。若来源没有确认人，不推断确认人。

在普通聊天的 `app_server_exec` 调研任务中，解析结果包含待确认项时，解析不能作为最终回复结束。必须先用原生 `request_user_input` 按每组最多 3 个问题向业务方补问确认；至少覆盖适用公司/院区、业务范围、上线阶段或期间，以及实际确认人和确认日期。确认前可以返回候选台账，但必须同时保留待确认清单并明确等待回答；不能只列“待业务签认”后结束，也不能把用户授权导入文件理解为业务确认。项目档案生成不适用此自动 QA 规则。

**当前工具限制：**`dy_research_record_write` 只有 `confirmed` 和 `retired` 状态，`confirmed=true` 会让该记录成为巡检可用结论；没有“来源已记录但业务待确认”的状态，也不能接受矩阵外的明细键。用户已明确：QA 表单中已填写的 A（回答）就是业务确认内容，可按已确认结论整理；空白 A、未回答问题及附件中的单纯观察不能据此视为业务确认。保留来源实际提供的答复人、日期；未提供时如实标为未提供，不得编造身份或日期。附件用于证据回链，不取代 A，也不自动扩大 A 的确认范围。导入授权本身不是业务确认。完整提取并不等于当前记忆工具支持完整落库。

## 写入边界和来源回链

模块事实只有在状态符合上述工具语义时，才通过 `dy_research_record_write` 按当前矩阵已定义的 `检查顺序 + 子项编号 + 适用范围` 保存；不要用普通记忆整文件覆盖模块调研历史，也不要自行创造检查键。QA 已填写的 A 按业务确认内容处理，结论需保留适用范围、差异和例外；附件作为依据并记录来源文件/页或定位信息，不能只写“见附件”。

调研记忆工具每条结论最多 2000 字符、范围最多 500 字符，字段不能含换行。应优先去掉重复表述，不得压缩掉会改变适用范围、业务差异、例外或验收含义的内容。超长内容若无法在现有检查键和字段限制内完整表达，暂停该部分，向用户说明确切限制和受影响来源范围；不能只留引用却声称全部明细已存入记忆。大量原始系统行、个人信息、银行账号、凭据及生产业务明细不写入项目记忆；按业务问题归纳必要结论，来源位置用于回查授权原件。

## 写后完整性验收

写入前后使用相同检查键清单比较，并按键调用 `dy_module_memory_read` 回读。最终至少核对并报告：

- 识别到的文件、工作表/页/幻灯片总数，以及成功提取数；
- 源结论/子项总数、映射到矩阵检查键数、成功保存且成功回读数；
- 空白或待确认项、未映射项、重复键、超长项、隐私排除项和解析失败项；
- 源文件位置回链是否覆盖每条已保存结论。

报告需区分：解析完整性、调研结论覆盖率、原始明细是否逐行入库、记忆写入覆盖率、业务确认状态。原始明细很多时，列出其数据行总数以及哪些归纳/排除/逐行保存，不把“全部调研结论已保存”说成“全部工作簿内容已记忆”。只有用户约定的覆盖范围内所有相关内容均已解析、每条有效结论均映射到可写状态并成功回读，且未确认、未映射、超长及失败项为零时，才报告该范围“完整导入”。用户要求全部原始明细逐行记忆时，必须逐行可回读；否则说明当前阻塞。保存来源事实不等于完成现场巡检或验收。

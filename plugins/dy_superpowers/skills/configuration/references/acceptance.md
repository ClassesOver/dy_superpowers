# 统一回读与浏览器验收

## 批次范围

- 项目/批次、环境 URL、数据库、Odoo/模块版本、公司/院区、业务日期、执行账号身份。
- 用户确认范围、确认摘要、幂等操作标识；不得保存密码、令牌或会话。
- 操作边界、风险、副作用、恢复路径；范围外及暂停项单独列出。

## 逐条配置

| 项目 | 内容 |
| --- | --- |
| 配置记录 | create/update、模型、真实记录 ID、业务唯一键 |
| 预期与实际 | 逐字段列旧值、确认目标值、MCP 实际值与差异；敏感字段脱敏 |
| 关联核对 | 真实关联 ID、目标模型、公司与业务日期适用范围 |
| 执行状态 | 未执行 / 已执行 / 失败 / 结果未知，不以超时判定未提交 |
| 数据回读状态 | 通过 / 不通过 / 未执行 / 结果未知；标明实际读取时间 |
| 浏览器验收状态 | 通过 / 不通过 / 未执行 / 受阻；独立于数据状态 |
| 证据 | MCP trace/调用标识、同环境同公司同 ID 的页面与截图相对路径；Knowledge reference 单列为规则依据 |
| 下一步 | 差异、受阻依赖项、责任方、重新确认或人工验收要求 |

## Playwright 检查

1. 使用已有受信浏览器会话。确认环境与数据库；若界面无法核对数据库，保留绑定证据，证据不足则受阻。不要加载任意外部 URL，不采集登录态。
2. 核对当前公司，打开该模型真实 ID 对应表单。菜单与 action 可从 Knowledge 定位，但按实际界面验证，不凭源码断言菜单可见。
3. 核对页面加载、记录身份、全部本批可见目标字段、关联记录显示及验收标准。隐藏字段只记 MCP 验证，界面不擅自点保存。
4. 用 Playwright 截图保存工作区，必要时遮挡无关个人信息；报告引用相对路径，不把完整响应、HTML 或登录凭据放入 trace。
5. 403、超时、错公司/记录、字段不符、无浏览器工具或无截图均不得记为浏览器通过。

批次汇总：逐项数据与浏览器都通过且无未决事项才是“配置验收完成”；否则给出通过项、阻塞项和下一步。报告与截图位于当前工作区 `.dy_superpowers/configuration/`，报告保存须用户确认，不写入插件参考目录。

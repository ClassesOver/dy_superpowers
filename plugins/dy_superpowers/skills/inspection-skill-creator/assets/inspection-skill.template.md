# {{业务域名称}}模块巡检

## 目标与输入

依据领域清单和确认调研，逐子项检查当前工作区单一项目的交付状态。执行前读取 [巡检通用流程](../../references/inspection-workflow.md)。

输入：{{项目/环境、软件版本、公司/账套、业务日期、岗位、交付范围和来源要求}}。缺失项按检查键发起调研，示例及模板不是项目事实。

## 适用范围

- 交付模块标识 `{{module}}`；调用上下文 `skill={{skill_name}}`。
- 检查键来自 [领域清单](references/inspection-matrix.md)，保持原始编号及逐子项标准。
- 业务重点与不适用边界：{{本期业务及制度义务}}。
- 当前能力：{{分别填写调研存储、矩阵键校验、只读诊断、正式巡检报告的已核实支持状态}}。

## 执行流程

1. 按通用流程核对项目范围，建立全部检查键及本轮纳入/排除项，按优先级组织工作。
2. 关联同范围确认调研，保留完整验收标准及所选分支；读取 [源码与查询](references/source-queries.md)，核对元数据后执行有范围的只读查询。
3. {{该领域必须验证的业务效果、岗位正反例及边界例}}。
4. 逐子项记录结果、证据、限制和阻塞，按当前能力执行校验及交付；部分范围结果说明覆盖度。

## 调研衔接

缺失、冲突、停用或范围不明时调用 `module-research`，传原 `trace_id`、检查键、完整标准和最小问题。确认后用调研工具保存并按同键及 `scope_id` 回读，只恢复有效 `confirmed` 子项；其他独立项继续。

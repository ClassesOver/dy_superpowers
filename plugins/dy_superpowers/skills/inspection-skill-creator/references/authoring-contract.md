# 巡检技能编写合同

## 文件职责

采用短入口和按需参考，目标目录通常为插件内 `skills/<业务域>-inspection/`：

- `SKILL.md`：触发条件、稳定模块标识、输入、领域范围/重点、执行路由及当前工具能力。
- 当前发布调研模板提供问题与附件要求；同范围最新确认答卷及关联附件提供业务要求，不另建静态巡检矩阵。
- `references/source-queries.md`：经核对的技术模块、模型、字段、关联、范围及只读配方，并注明源码位置/版本和未核实部分。

共享流程位于插件 `references/inspection-workflow.md`；报告字段及门禁规则引用 `docs/inspection-validation.md`。不要把通用规则复制到每个领域，防止修订漂移。模板中的相对路径按实际输出目录解析；移植到插件外时复制必需共享资源并修正引用，不留下本机绝对路径依赖。

## 每个检查子项的语义

检查定义至少包含以下信息，载体可以是清单或具名结构，不以物理行、列号作为业务键：

- `question_id`：当前模板返回的真实问题标识；不同来源先明确映射，重复键、缺项和冲突分别列出，不编造编号。
- 配置分类/配置项、优先级、定位路径和业务目的。
- 调研问题及需确认的公司/账套、岗位、业务、期间、制度、例外和生效边界。
- 适用条件与不适用依据；后期能力的本期衔接要求。
- 完整验收标准、条件分支、最小证据和验证方法；已知缺陷、材料缺口与未验证状态分别表达。

检查定义不是项目事实。模板中出现“已配置”、数量或示例不得当作当前结果。执行结果以 `module/question_id/scope_id/environment` 关联，并绑定当前答案版本及修订；显示名变更不改变稳定键，答案或附件变化后重新准备巡检。

## 源码与配方核查

对每个拟执行的模型记录源码模块/文件、版本依据及以下结论；源码缺失或定制版本不一致时明确限制，并在真实执行前核对元数据：

1. 模型属于持久配置、业务结果还是临时操作向导。临时向导仅用元数据了解接口，不作持久状态证据，不执行其方法。
2. 字段是否存在、类型和关联是否正确，计算字段能否搜索，字段是记录归属还是界面候选列表。不能仅凭 `company_id/company_ids` 名称选择 domain。
3. 公司/结构/账套范围如何确定，共享记录为空的真实语义是什么，子行按自身还是父头限定；无范围依据时停止该配方，不退回无界限查询。
4. 启用/归档、业务起止日期及计算时钟；目标业务日期与服务器今天、来源核查日及历史数据库快照分别表达。
5. 最小输出字段、每页限制、offset 与 ID 完整性检查、超上限/重复/失败的停止条件。有关联明细时分页取全，父头数量不能证明子行完整。
6. 读取结果能证明的配置事实以及仍需岗位、流程、金额/日期边界、权限或防重样例的部分。安装或记录数量不等于业务生效。

参考费用/总账查询了解这些问题的具体处理，但不能将其空公司、日期或状态约定推及新领域。Odoo 仅调用现有只读工具，context 只支持布尔型 `active_test`；不引入任意 RPC、SQL、管理员切换或业务写方法。

## 能力声明与接入

能力以当前代码和实际可用工具为准，不能仅按工具名称推断：

- 确认答卷：费用、总账答卷由调研流程批次保存；巡检只用 `dy_module_memory_read` 读取当前确认答案，不导入或保存答案。历史记录不作为当前巡检依据；新领域须先核实模板及答卷工具是否接入。
- 只读诊断：模块/字段/记录工具可查询授权账号允许的模型；模型存在和账号权限须现场确认。技术模块名与交付模块标识不是同一概念。
- 正式巡检：当前 `dy_inspection_validate` 和报告保存/读取/PDF 导出仅接受费用和总账。`valid`、`gate`、证据真实性和业务执行授权分别说明；合法的失败或待确认报告也可经用户确认保存。

新领域尚未接入时，入口必须说明：可进行具名检查记录及人工复核，不能调用正式巡检工具获得该域门禁或自动保存。不得借费用/总账标识包装新域数据，也不得直接写内部文件伪造工具记录。

若明确要求新增正式支持，另行实现并测试模板加载、问题标识约束、工具 schema、覆盖/答案版本/证据校验、单模块报告保存回读和 PDF 导出、来源适配与端测。仅扩展模块枚举或复制 skill 不能算接入完成。

## 发布与恢复

每个 `module/scope_id/environment` 分别核对纳入及排除项的完整覆盖。必须保留完整验收标准，分支选择另写理由。Odoo 证据须关联同工作区的成功调用、正确检查键/范围/环境/调研版本，不能只记录 trace_id。报告按单模块输出，部分范围结论显示覆盖度。

生产流程默认只读，失败时保持已知覆盖和待办；不通过重复查询、切管理员或修改配置追平数量。恢复后重读最新答卷，检查范围、环境和证据时效，答案或附件变化先复查。记忆仅当前工作区，更新需要确认和修订检查；标准包与项目事实分开保存。trace 使用已有脱敏规则，不记录业务返回行或新增遥测。

完成状态分别列为：技能文档已生成、包与场景验证结果、正式工具是否接入、真实环境是否已验证、业务签认是否完成。公开草稿必须明确缺口；未做 live 验证不得声称生产验收完成。

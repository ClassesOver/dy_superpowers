# 插件扩展契约

后续工作流应遵循以下合同：

1. 收集最少输入并标明未知项和来源。
2. 先生成计划，再校验目标环境、权限、风险、依赖和验证方法。
3. 每次 MCP 调用携带 `trace_id`，写操作必须有明确的目标级授权。
4. 执行后重新读取受影响状态，验证失败不能报告为成功。
5. 只持久化用户确认的工作区记忆，不把动态外部状态当作记忆。

`dy_validate_plan` 只检查计划结构和写操作的审批前置条件。`valid=true` 不代表获得用户授权，也不能作为执行写操作的凭据。

运行追踪仅保存短标识、受控状态和不含业务正文的证据引用；证据内容、员工信息和生产业务明细保留在原系统或授权工作区，不写入 trace。

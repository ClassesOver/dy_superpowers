# 插件扩展契约

后续工作流应遵循以下合同：

1. 收集最少输入并标明未知项和来源。
2. 先生成计划，再校验目标环境、权限、风险、依赖和验证方法。
3. 每次 MCP 调用携带 `trace_id`，写操作必须有明确的目标级授权。
4. 执行后重新读取受影响状态，验证失败不能报告为成功。
5. 只持久化用户确认的工作区记忆，不把动态外部状态当作记忆。

计划结构检查尚未形成独立业务闭环，因此不作为公开 MCP 工具提供。所有 Odoo 操作仍限于只读查询。

运行追踪按工作区哈希标识分组，并记录经用户确认的记忆正文和 Odoo 搜索 domain，以便审计调用内容。凭据和常见个人字段值脱敏，Odoo 返回行及证据正文不写入 trace；单条记忆正文限制为 64 KiB。这些内容只保留在本地 JSONL trace 中，不发送到任何外部服务。

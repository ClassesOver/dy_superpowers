# 运行边界与兼容迁移

## 出站目标

插件不使用外部遥测，唯一的出站目标类别是 Odoo。`APP_URL` 同时提供 Odoo 连接地址和受信任来源，必须是精确的 HTTP(S) origin，不能使用通配符或 URL 路径。连接参数另使用 `DB_NAME`、`APP_USER` 和 `APP_PASSWORD`。`DB_HOST`、`DB_PORT`、`DB_USER` 和 `DB_PASSWORD` 由工作区环境加载器透传，但插件不会用它们直接连接数据库。

校验拒绝无 scheme 或 host、非 HTTP(S)、用户信息、查询、片段、非法端口和非法主机名；拒绝字面量链路本地地址、未指定地址和组播地址。未授权的公网、私网和环回 origin 一律拒绝。内网 Odoo 需要精确授权；显式授权 HTTP 表示接受该目标的明文连接风险，远程部署推荐 HTTPS。

Odoo JSON-RPC 使用独立 requests Session，关闭环境代理和自动重定向；登录和调用的请求超时为 20 秒。

允许列表与连接变量属于受信任的进程部署配置，不能交给工具参数或项目记忆控制。本策略无法防御可以同时篡改进程环境、允许列表或受信任域名 DNS 的攻击者；精确授权域名也包含对其解析结果的信任。需要限制解析后的网络范围时，应在部署环境配置出站防火墙。本策略不宣称提供 DNS 重绑定隔离。

## 工具、连接与工作区

工具按领域分布在 `mcp-server/src/dy_superpowers_mcp/tools/`（session、research、inspection、memory、odoo、knowledge、configuration），各模块的 `TOOLS` 由 `tools/__init__.py` 汇总为 `TOOL_REGISTRY`，它是工具说明、JSON Schema 和处理器的唯一注册源；重复注册在启动时失败。公共运行时（参数错误转换、本地 trace、Odoo 连接缓存与查询审计）位于 `tools/runtime.py`，`server.py` 只负责协议入口。服务仅使用锁定的 MCP 2.x SDK 和 jsonschema；SDK 或必需依赖缺失时明确启动失败，不启动第二套手写协议。SDK 错误保留数值代码，脱敏错误不回显参数正文。

`dy_odoo_record_search` 是公开搜索工具。旧工具名不再接受，调用统一使用当前 MCP 工具清单。

进程仅缓存一份 Odoo 客户端，复用登录 UID 及 HTTP Session。工作区或任何连接配置变化时关闭旧连接并重建；远程调用失败后清空缓存，下次重新认证，不在失败请求内自动重试。Odoo JSON-RPC 请求通过锁串行化，其他工具不占用此锁。SDK 退出时关闭缓存连接。

工作区解析顺序为服务参数 `--workspace`、`DY_WORKSPACE_ROOT`、启动目录。使用启动目录时输出提示。显式配置也必须是存在的项目目录，不能指向插件安装目录或其子目录。一个 MCP 进程固定服务一个工作区；环境变量应在启动前设置。

## 本地追踪保留

每个工作区的日志目录默认限额为 100 MiB，保留最近 30 个 UTC 自然日（当天及此前 29 天）。按 trace 和 UTC 日期写入独立文件，使用标准库 RotatingFileHandler 实现每文件 5 MiB 轮转及一份备份；跨日读取按事件时间合并，同一时间先读备份。目录锁串行化追加、轮转、清理与读取。配额包含不同 trace_id 和轮转备份，超额按最早修改时间删除文件，不跨工作区清理。追加或读取时按文件日期执行清理，持续调用和修改文件时间不会延长过期日志的保留期，无独立后台清理进程。

旧版未带日期的 JSONL 及其备份仍可读取，按事件的 UTC 日期清除过期行，保留有效行原文。旧文件出现残行、无效时间戳、UTF-8 解码错误，或日志文件名日期不合法时，保留原文并告警，该文件退回按修改日期清理，仍计入目录容量配额；不会阻断其他 trace 的写入或读取，需恢复备份后查询损坏日志。

本地日志不是永久审计档案，清理可能删除一条 trace 的部分或全部历史；需要长期存储时应在工作区外部自行归档。日志磁盘错误不阻断业务；单条超限事件拒绝写入并提示。

每条本地事件都包含 `workspace_id`，由工作区绝对路径 SHA-256 截取 16 位十六进制字符生成；不会记录工作区路径或目录名。可按 `workspace_id` 筛选一个项目的全部事件。

按项目要求，记忆读取/写入会记录正文，记忆搜索会记录查询词和返回摘要，调研读写会记录当前记录，Odoo 搜索会记录 domain 条件。凭据及常见个人字段值会脱敏；Odoo 返回记录行不写入 trace。记忆正文单条上限为 64 KiB，超限时保留前缀并设置 `content_truncated=true`；Odoo domain 序列化后最多 2048 字符，超限或结构过深时省略并设置 `domain_truncated=true`。这些内容只保留在本地 JSONL trace 中。

## 调研 Markdown

新记录只保留一份 JSON 代码块正文和摘要，旧格式继续兼容读取。摘要用于发现意外编辑，并非签名或防篡改认证。确认、修订版本、范围生命周期及历史保留规则不变。

完整边界用逐行扫描解析，残块不再被正则跳过。能够识别身份的损坏记录阻断对应范围，修复需用户确认并携带当前块版本。无法识别身份的完整损坏块保留并告警；边界损坏须人工恢复备份，不能直接创建重复记录掩盖错误。

修复按用户提供的 `expected_revision` 定位原始块，范围字段损坏时仍可使用重新确认的范围内容恢复；合法的旧范围标识尽量沿用，显式提供的新标识优先，无法恢复标识时按确认范围生成。不得与其他范围记录冲突。

损坏原文按 SHA-256 存入当前模块记忆目录 `.dy_superpowers/modules/<module>/history/<摘要>.md`，当前记录的 `history` 只保存 `history/<摘要>.md` 快照引用；读取工具仍返回 `original_block`，兼容既有历史查看。后续修复不会再把原始块连同全部历史递归塞回当前 Markdown；旧的内嵌原文在下次确认修复时归档。快照只允许位于当前工作区，读取时校验摘要；备份工作区记忆时须同时备份各模块的 `history/` 子目录。快照本身缺失或摘要错误时明确要求恢复备份，不能用重新确认当前结论伪造丢失的历史。快照先原子保存，再替换当前记录；若中途失败，最多留下未引用的快照，原记录仍保留。


## 链路与业务标签

每次工具调用的生命周期通过 `tool.start` / `tool.error` / `tool.end` 事件记录；不同 MCP 调用按工作区隔离的 `workflow_id` 聚合。可选 `trace_context` 仅接受技能、模块、检查顺序、子项、稳定范围及版本标识，不能改变工作区或工具身份。调用方自报事件可以携带业务标签与结果，不能伪造生命周期、远程关联标识或工具执行状态。标签不构成业务事实或权限。

本地事件保存可筛选元数据，记忆/调研正文和搜索词按项目要求记录在事件中，domain 脱敏后记录。失败查询在请求前记录 domain 元数据；未通过参数检查的查询不会当作已执行请求记录。错误事件不含异常正文或堆栈，仅保留脱敏错误类别和错误码。工具正常结束不代表巡检通过，巡检结论和记录有效性须另看 `result` 与 `valid`。

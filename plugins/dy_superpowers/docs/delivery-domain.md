# HRP 项目交付领域

一个工作区只承载一个项目。交付模型建立以下关联：

`业务需求 -> 交付物/验收条件 -> Odoo 配置对象 -> 计划步骤 -> 审批/执行记录 -> 验证证据`

项目阶段与并行工作项状态相互独立。交付门禁根据当前有效的验收证据计算；不能仅凭对话或记忆将项目标记为已验收或可交付。

每条证据记录其来源、来源版本或引用、采集时间、验证方法、结果、适用范围和限制。缺失、过期、不可用或冲突的证据应保持为未知或阻塞状态。

## 巡检记录与复查

当前结果保存在工作区 `delivery-register.md`，使用既有记忆工具更新，不新增数据库。每个“模块 + 模板问题 + 适用范围”单独记录，不混用公司或期间。记录至少包含：

| 字段 | 要求 |
| --- | --- |
| 记录标识、前次记录 | 本次唯一标识；复查引用前次记录，保留原结果 |
| 问题与范围 | 模块、模板问题、公司/账套/期间和环境 |
| 答案修订 | 当前确认答案的修订、`scope_id`、确认日期和范围；缺失时说明阻塞 |
| 验收依据 | 当前确认答案提取的全部要求，以及绑定附件的引用、SHA-256 与已确认明细 |
| 验证信息 | 验证时间、方法、最小证据引用与证据限制；不保存业务正文 |
| 结果与理由 | 通过、部分通过、不通过、不适用、待确认、未检查或未知，附理由 |
| 问题与复查 | 阻塞原因、下一步、复查状态及替代关系 |

答卷缺失或不明确时标待确认，由用户另行安排调研；连接失败、权限不足或证据缺失不等同于不通过。只有适用要求全部通过且不存在未决阻塞时，问题才可汇总通过；全部不适用时列明依据。存在失败项则汇总不通过，存在未知或未检查则保持待确认；部分通过须逐项说明剩余缺口。

答案修订、附件、环境或范围变化时，相关旧结果只能作为历史，须复查后才能重新用于交付判断。`dy_inspection_validate` 校验当前模板全部问题的覆盖、必填字段、证据引用、答卷版本、验证时间及附件要求对应关系，并给出该范围的门禁状态。业务证据真实性和整个项目的范围完整性仍由顾问核实；详见 [巡检校验合同](inspection-validation.md)。通用记忆写入不自动调用校验，技能须先校验再展示并确认保存。
